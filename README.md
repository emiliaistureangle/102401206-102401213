## 一、项目简介

面向校园学生的失物招领信息平台。同学可以集中发布**寻物**与**招领**信息，按关键词搜索物品、查看详情并联系发布者，物品找到后可自行修改信息状态。

目标是替代分散在班级群、宿舍群、朋友圈里的失物信息，解决三个问题：**信息分散**、**容易被群消息刷掉**、**没有统一搜索入口**。

本次作业只完成**需求分析与原型设计**，不涉及后端、实名认证、即时聊天、地图定位等复杂功能。

## 三、原型说明

### 3.1 页面清单

| 序号 | 页面 | 说明 |
| --- | --- | --- |
| ① | 首页 | 搜索框、全部/寻物/招领筛选、信息列表、悬浮发布按钮 |
| ② | 发布信息页 | 选寻物/招领，填写物品名称、分类、地点、时间、描述、联系方式 |
| ③ | 搜索页 | 关键词搜索、热门搜索词、类型/时间筛选、结果列表 |
| ④ | 信息详情页 | 物品大图、类型与状态、分类/地点/时间/联系人、收藏与联系 TA |
| ⑤ | 发布成功页 | 成功反馈与下一步引导 |
| ⑥ | 我的（发布 / 收藏） | 发布统计、标记「已找到 / 已归还」、收藏列表 |

### 3.2 交互是真实的

原型内置 7 条示例数据，下列操作会**真正改变列表内容与状态**，不是静态截图：

1. 首页点击「全部 / 寻物 / 招领」→ 列表按类型过滤
2. 搜索页输入关键词回车（或点「搜索」）→ 结果实时更新，显示「找到 N 条」；热门搜索词一点即搜；类型/时间筛选生效
3. 详情页点「☆ 收藏」→「我的 → 我的收藏」中可见，标签上带数量角标
4. 发布页填写并「立即发布」→ 新信息出现在首页和「我的发布」中
5. 「我的发布」中标记「已找到 / 已归还」→ 状态与统计即时更新，首页同步变化
6. 右上角「全部页面平铺」→ 一次性查看全部 6 个页面，方便截图

> 数据保存在内存中，**刷新页面会恢复初始的 7 条示例数据**，这是原型的正常行为。

### 3.3 本地预览

方式一：直接双击 `prototype/index.html`
方式二：在项目目录执行 `python -m http.server 8000`，浏览器访问 `http://localhost:8000/`

## 四、部署到 GitHub Pages（生成在线链接）

> 包含**两人分工、A/B 两份博客的差异、PR 协作流程与时间安排**的完整版见
> [`docs/结对协作与提交步骤.md`](./docs/结对协作与提交步骤.md)。下面只保留最关键的推送与部署命令。

1. 在 GitHub 新建 **Public** 仓库，例如 `campus-lost-and-found`（不要勾选 Add README）
2. 在本地项目目录执行：

```bash
git init
git add .
git commit -m "docs: 完成需求分析与原型设计"
git branch -M main
git remote add origin https://github.com/<你的用户名>/campus-lost-and-found.git
git push -u origin main
```

3. 打开仓库 **Settings → Pages**，Source 选 `Deploy from a branch`，Branch 选 `main` + `/ (root)`，点 Save
4. 等 1—2 分钟，访问：

```
https://<你的用户名>.github.io/campus-lost-and-found/
```

根目录的 `index.html` 会自动跳转到 `prototype/`，所以这个短链接就是**原型在线链接**，可直接填进博客。

> 如果推送时报 `Failed to connect to github.com:443`，说明 git 没走代理。可在单次命令中加代理参数（不要写进全局配置）：
> `git -c http.proxy=http://127.0.0.1:7897 -c https.proxy=http://127.0.0.1:7897 push -u origin main`

## 五、设计要点速览

- **主色** `#2F6BFF`；寻物标签橙红 `#FF6B4A`，招领标签绿 `#0FA968`
- **发布流程**先选「我丢了东西 / 我捡到东西」，字段语义随之切换（丢失地点 ↔ 拾取地点）
- **联系方式**中间四位打码，兼顾联系需要与隐私保护
- **状态管理**是核心：物品找到后标记「已解决」，避免继续被同学打扰
- **联系方式只展示、不做即时聊天**——这是本次有意砍掉的功能，为第二次结对编程降低实现难度

## 六、为第二次结对编程预留的接口

小程序页面与原型一一对应：

| 原型页面 | 小程序页面 |
| --- | --- |
| 首页 | `pages/index` |
| 发布信息页 | `pages/publish` |
| 搜索页 | `pages/search` |
| 信息详情页 | `pages/detail` |
| 我的 | `pages/my` |

云数据库只需一张 `items` 集合，建议字段：`_id`、`type`(lost/found)、`title`、`category`、`place`、`happenAt`、`desc`、`images`、`contact`、`nickname`、`status`(open/done)、`createdAt`、`views`。
对 `type`、`title` 建索引即可支撑浏览与搜索。
