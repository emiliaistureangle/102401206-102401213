# 结对协作与提交步骤（含分工方案）

> 配套文件：`blog/博客园正文-成员A.md`、`blog/博客园正文-成员B.md`、`blog/结对过程与个人总结.md`
>
> **下文中「成员A」= 吴怡霏 102401206（需求与文档），「成员B」= 薛锦荣 102401213（原型与测试）。**

---

## 〇、先想清楚两个问题

### 问题 1：GitHub 要建几个仓库？

| 方案 | 适用情况 | 说明 |
| --- | --- | --- |
| **✅ 方案一（推荐）：一个共享仓库** | 老师按"结对小组"评作业 | A 建仓库并邀请 B 为 Collaborator，**两人各自提交（PR）**，仓库的历史里能同时看到两个人的名字——这才叫"用 GitHub 协作"，也是作业要求 15 的本意 |
| 方案二：两个仓库 | 老师明确要求"每人一个仓库/各自独立提交" | B 在 A 的仓库页面点 **Fork**，得到自己账号下的副本，再各自开 Pages |

**本指南按方案一写。** 如果最后需要方案二，只需在第 5 步之后让 B 点一下 Fork 即可。

### 问题 2：为什么是"两份博客"而不是"两篇不同内容"？

作业要求 13 说得很明确：**主体内容可以保持一致，但个人总结应分别完成。**
所以两份博客的差异只有三处：

| 内容 | 博客-A | 博客-B |
| --- | --- | --- |
| 抬头署名 | 成员A 在第一行（标注"本文作者"） | 成员B 在第一行（标注"本文作者"） |
| 第五节分工列表顺序 | 成员A 的职责在前 | 成员B 的职责在前 |
| 第七节个人总结顺序 | A 的总结在前 | B 的总结在前 |
| 其余正文 / 表格 / 流程图 / 在线链接 | **完全相同** | **完全相同** |

## 一、分工方案（两边都对等）

原则：**每个阶段一人主导、另一人参与评审**，两人的主导次数和总工作量尽量接近。

| 阶段 | 主导 | 参与 / 评审 | 主要产出 | 预估 |
| --- | --- | --- | --- | --- |
| 1. 需求分析 | 成员A | 成员B | 用户角色表、需求归纳 | 2h |
| 2. 功能清单与优先级 | 成员A | 成员B | 功能清单 FR-01—FR-08 | 1h |
| 3. 流程图设计 | 成员B | 成员A | 3 张基本流程图 | 1h |
| 4. 原型设计（页面 / 交互） | 成员B | 成员A | 6 个页面、在线原型 | 4h |
| 5. 流程走查与测试 | 成员B | 成员A | 走查记录、修改清单 | 1h |
| 6. 在线部署 / 仓库维护 | 成员A | 成员B | GitHub 仓库、Pages 链接 | 0.5h |
| 7. 博客撰写 | 成员A 起草 | 成员B 校对 | 博客正文 | 2h |
| 8. PSP 与个人总结 | 各自 | 互审 | PSP 表 + 两段总结 | 0.5h |

**工作量小结**：成员A ≈ 6h，成员B ≈ 7h。

> 注意：**原型设计是本次作业的核心产出**（作业重点就是"需求分析和原型设计"），由成员B 主导。写博客时请务必把这一点写清楚，避免出现"某人看起来没做什么"的观感。

## 二、操作步骤（按顺序做）

### 第 1 步 · 成员A：建仓库并邀请协作

1. GitHub 新建仓库，名称建议 `campus-lost-and-found`，**选 Public**，不要勾选 "Add a README file"
2. 进入仓库 **Settings → Collaborators → Add people**，输入成员B 的 GitHub 用户名
3. 成员B 查收邮件/通知，点 **Accept invitation**

### 第 2 步 · 成员A：首次推送（第 1 次上传）

在项目目录 `软工小程序` 下执行：

```bash
git init
git add .
git commit -m "feat: 完成需求分析、原型设计与设计文档"
git branch -M main
git remote add origin https://github.com/<A的用户名>/campus-lost-and-found.git
git -c http.proxy=http://127.0.0.1:7897 -c https.proxy=http://127.0.0.1:7897 push -u origin main
```

> 如果报 `Failed to connect to github.com:443`，说明 git 没走代理，加 `-c http.proxy=... -c https.proxy=...` 即可（只在单次命令里加，不要写进全局配置）。
> 如果弹出凭据窗口，由本人完成授权，不要把密码或 token 交给任何人。

### 第 3 步 · 成员B：克隆并提交自己的部分（第 2 次上传）

```bash
git clone https://github.com/<A的用户名>/campus-lost-and-found.git
cd campus-lost-and-found

git checkout -b docs/summary-b          # 新建自己的分支
# 打开 blog/结对过程与个人总结.md，把成员B 的个人总结改成自己的真实感受
# 可另存一份 blog/个人总结-成员B.md

git add .
git commit -m "docs: 补充成员B的个人总结与流程走查记录"
git push -u origin docs/summary-b
```

推送后回到 GitHub 仓库页面 → 点 **Compare & pull request** → 填写说明 → **Create pull request**
然后由成员A 点 **Files changed** 检查 → **Review changes** → **Merge pull request**。

### 第 4 步 · 成员A：补自己的总结（第 3 次上传）

同理：新建分支 `docs/summary-a` → 写自己的总结 → push → 开 PR → 由**成员B** Review 后合并。

> **强烈建议截图保存这两个 PR 页面**，作为"结对过程"的证明材料（作业要求 11）。提交记录里两人的名字 + 互相 Review，比任何文字描述都有说服力。

### 第 5 步 · 成员A：开启 GitHub Pages，拿到在线链接

仓库 **Settings → Pages** → Source 选 `Deploy from a branch` → Branch 选 `main` + `/ (root)` → **Save**

等 1—2 分钟，访问：

```
https://<A的用户名>.github.io/campus-lost-and-found/
```

根目录的 `index.html` 会自动跳转到原型，所以这个短链接就是**原型在线链接**，直接填进两份博客。

> 若老师要求各自独立：成员B 在仓库页点 **Fork**，进入自己账号下的副本 → Settings → Pages → 同样开启 → 得到 B 自己的链接。

### 第 6 步 · 各自：填博客里的个人信息

两份博客里各有 **两处**【】占位需要填：

1. 开头的 **学号 + 姓名**（两人都填）
2. 第七节个人总结里的 **姓名 + 学号**（两人都填）

另外把 **原型在线链接** 填到开头（两份填同一个链接）。

### 第 7 步 · 各自：插入图片

两份博客都要插入：

- **6 张原型截图**：首页、发布信息页、搜索页、信息详情页、发布成功页、我的
  （打开原型 → 点右上角「全部页面平铺」可以一次截全 6 页）
- **1—2 张结对过程截图**：建议用 GitHub 的 PR 页面截图 + 讨论照片

### 第 8 步 · 填 PSP 实际耗时

按真实情况填写，**合计要与各项相加一致**。如果某项明显超出预估，补一句原因反而是加分项（例如"原型工具不熟，比预估多花 1.5h"）。

### 第 9 步 · 各自发布博客

- 成员A 用 A 的博客园账号发布 `博客园正文-成员A.md`
- 成员B 用 B 的博客园账号发布 `博客园正文-成员B.md`
- 发布后**互相读一遍**，检查对方的个人总结是否写成了自己的事（别搞混）

### 第 10 步 · 各自提交作业

两名同学**分别在作业系统提交**，各自贴上自己那篇博客的地址。

## 五、常见问题

**Q：两份博客内容几乎一样，会不会被判定为抄袭？**
不会。作业要求 13 明确写了"两人的主体内容可以保持一致"，这是结对作业的正常做法，差异体现在署名和个人总结上。

**Q：正文 1049 字，加上个人总结 1388 字，超了 1200 怎么办？**
"800—1200 字"一般指正文叙述部分，PSP 表格和个人总结通常单独计算。如果老师严格按全文数，最简做法是删掉第二节的功能表格（表格里 8 行说明约 160 字），正文立减。

**Q：成员B 没有仓库的 Pages 权限怎么办？**
Pages 是在仓库所有者账号下开启的，成员B 不需要权限。两份博客填同一个链接即可；如果必须各自有链接，就让成员B Fork 一份。

**Q：git push 一直失败？**
先确认网络：浏览器能打开 `https://github.com` 说明网络没问题，是 git 没走代理；如果弹出凭据窗口且报 `Invalid username or token`，说明 Windows 凭据管理器里保存的旧凭据失效了，需要清除后重新授权。
